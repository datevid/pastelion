# Plan de Migración Arquitectónica: URLs Cortas Deterministas (UUID + BIGSERIAL)

## 📌 Contexto
Actualmente, el sistema genera URLs cortas utilizando un disparador (Trigger) en PostgreSQL que selecciona 7 caracteres aleatorios (Base62). Aunque la probabilidad de colisión es ínfima, estadísticamente es posible.

Para alinear el proyecto con una arquitectura de escala global (estilo "Arquitectura de Libro"), migraremos a un modelo **Determinista y Matemático** utilizando Ofuscación Secuencial (implementada a través de la librería `hashids` con alfabeto Base58).

Este nuevo modelo garantiza **CERO COLISIONES** matemáticas, ofuscando un ID interno numérico en una URL corta segura y legible, manteniendo al mismo tiempo nuestro `UUID v4` actual nativo en la nube para la replicación y seguridad del registro.

---

## 🛠️ Fases del Desarrollo

### Fase 1: Modificaciones en la Base de Datos (Supabase)
1. **Crear columna secuencial:** 
   Agregaremos una nueva columna numérica autoincrementable a la tabla `pastes` (o `notes`).
   ```sql
   ALTER TABLE pastes ADD COLUMN internal_id BIGINT GENERATED BY DEFAULT AS IDENTITY;
   ```
2. **Eliminar la lógica aleatoria antigua:**
   Ya no necesitamos que PostgreSQL calcule la URL aleatoria, por lo que removeremos el Trigger y la Función.
   ```sql
   DROP TRIGGER IF EXISTS tr_generate_short_url ON pastes;
   DROP FUNCTION IF EXISTS public.generate_short_url();
   ```

### Fase 2: Configuración del Proyecto (Next.js)
1. **Instalación de Dependencias:**
   Instalaremos el algoritmo de ofuscación de IDs.
   ```bash
   npm install hashids
   ```
2. **Variables de Entorno:**
   Agregaremos un "Salt" (una llave criptográfica) a nuestro `.env.local` para que nadie más pueda predecir o aplicar ingeniería inversa a nuestros IDs matemáticos, aunque sepan la fórmula.
   ```env
   HASHIDS_SALT="un_secreto_super_seguro_y_aleatorio"
   ```

### Fase 3: Modificación del Backend (`src/app/actions/paste.ts`)
1. **Importar y Configurar Hashids:**
   Configuraremos la librería para usar el **Alfabeto Base58** para evitar confusiones visuales (0, O, I, l).
   ```typescript
   import Hashids from 'hashids';
   const hashids = new Hashids(
       process.env.HASHIDS_SALT, 
       7, // Longitud mínima de 7 caracteres
       '123456789ABCDEFGHJKLMNPQRSTUVWXYZabcdefghijkmnopqrstuvwxyz' // Base58
   );
   ```

2. **Refactorizar `createPaste`:**
   El nuevo flujo de inserción de un paste operará de esta manera:
   * **Paso A:** Se inserta el texto encriptado en Supabase (Supabase genera el `UUID` y el `internal_id` temporal). Next.js pide que la base de datos le devuelva ese `internal_id`.
   * **Paso B:** En Next.js, se toma el `internal_id` (Ej: `1`) y se ofusca: `hashids.encode(1)` lo cual genera algo como `xK8pL9m`.
   * **Paso C:** Next.js envía inmediatamente un `UPDATE` a Supabase guardando esta nueva URL corta (`short_url`) en el registro que se acaba de crear usando su `UUID`.
   * **Paso D:** Se devuelve la nueva URL corta al front-end para que el cliente sea redirigido.

### Fase 4: Pruebas y Validación
- Crear múltiples pastes consecutivos para verificar que la longitud y el alfabeto Base58 sean correctos.
- Intentar acceder al paste usando la nueva URL generada.
- Revisar los logs para confirmar que el proceso dura sólo unos milisegundos a pesar del "doble viaje" (Insert/Update) a la base de datos.
